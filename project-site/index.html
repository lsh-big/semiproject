01 / PROJECT OVERVIEW

옷을 고르는 순간을
나를 이해하는 경험으로.

취향을 입력하고, 나에게 맞는 코디를 발견하고, 마음에 든 아이템을 저장하는 흐름을 하나의 서비스 안에 설계했습니다.

온라인에서 옷을 살 때는 마음에 드는 스타일을 찾는 일과 실제로 나에게 어울릴지 판단하는 일이 따로 떨어져 있습니다. ONFIT은 이 과정을 스타일 프로필 → 코디 탐색 → 아이템 저장 → 핏 확인의 사용자 여정으로 연결합니다.

메인 화면은 패션 에디토리얼의 분위기를 살리고, 각 기능 화면은 같은 색상과 타이포그래피 체계 안에서 이어지도록 구성했습니다. 데스크톱뿐 아니라 작은 화면에서도 주요 탐색과 사진 선택을 사용할 수 있도록 반응형 UI를 적용했습니다.

이 소개 페이지에서 볼 수 있는 것

ONFIT의 화면별 목적, 각 화면에서 사용자가 할 수 있는 일, 기능을 연결한 프론트엔드·API 구현 흐름, 기술 스택과 현재 데모 데이터의 범위를 한곳에 정리했습니다. 실제 서비스는 별도 체험 링크에서 열 수 있습니다.

02 / WHAT ONFIT DOES

발견부터 착용까지,
아홉 가지 경험.

각 기능은 별도 화면으로 나뉘지만 공통 내비게이션과 재사용 UI 컴포넌트로 한 서비스처럼 연결됩니다.

선호 스타일, 자주 입는 색, 원하는 핏을 선택해 취향의 기준을 만듭니다.

사진 속 원하는 아이템을 표시해 유사 상품을 찾고 가상 착용을 이어갑니다.

04 / HOW IT WAS BUILT

화면을 기능으로,
기능을 흐름으로.

UI를 작은 컴포넌트로 나누고, 데이터가 필요한 지점은 서비스 함수와 API로 연결했습니다.

STEP 01

사용자 여정 설계

프로필 설정에서 코디 탐색, 아이템 저장, 피팅까지 이어지는 주요 이동 경로를 화면 단위로 정리합니다.

STEP 02

재사용 가능한 UI

Header, ProductCard, LookCard, StyleChips와 같은 공통 요소를 분리해 페이지 간 동작과 스타일을 맞춥니다.

STEP 03

상태와 API 연결

React state/effect로 입력·로딩·오류·완료 상태를 관리하고, 서비스 모듈에서 FastAPI에 JSON 또는 이미지 FormData를 전송합니다.

STEP 04

반응형·배포

Vite로 정적 파일을 빌드하고 GitHub Actions가 Pages용 산출물을 업로드합니다. 소개 페이지와 앱은 서로 다른 경로로 배포됩니다.

07 / TEAM CONTRIBUTION

역할을 나누고
하나의 서비스로 연결.

저장소에 기록된 팀 담당 영역입니다. 각 담당 기능은 공통 UI와 API 흐름 안에서 통합됩니다.

프로젝트 기여 영역

이승호 — 가격 이력, 구매 타이밍 분석, 가격 수집 자동화
성승건 — 회원·프로필, 개인 맞춤 코디, 인바디, 3D 피팅 및 관련 프론트엔드·백엔드
황상옥 — 공통 프론트엔드와 UI
안종범 — 상품 크롤링, 동일 상품 매칭, 가격 비교

데모 범위 안내 · GitHub Pages는 정적 호스팅이라 API 서버나 데이터베이스를 자체 실행하지 않습니다. 현재 코디·가격 일부는 시연용 데이터이며, 로그인·프로필 저장·이미지 AI 검색 등 서버 연동 기능은 별도 백엔드 배포와 API 주소 설정이 필요합니다. 가격 타이밍 화면은 기록이 충분히 쌓이기 전까지 구매 적기 분석을 제공하지 않습니다.
